# Detroit Root Network release - September 21, 2026

## Release contents

This candidate contains the Nile-and-Quinn-approved Lovable changes described in
`HANDOFF-TO-LOVABLE/RETURN-TO-CODEX-2026-09-21.md`, plus one release correction
found during Codex validation.

## Required deployment order

1. Create a Git branch from current `main` and copy this candidate into it.
2. Review the changed-file list and commit the candidate without ZIPs,
   `node_modules`, `.next`, environment files, or local output folders.
3. Push the branch and deploy it to a Vercel Preview.
4. In Supabase SQL Editor, apply all of
   `supabase/migrations/013_grow_plot_dimensions.sql` to the same project used by
   the Preview. Migration 013 must be present before Farmers Grow saves are
   tested.
5. Run the preview acceptance checks below.
6. Merge the reviewed branch to `main`. Confirm the production Vercel deployment
   uses the existing environment variables. Migration 013 does not add a Vercel
   variable.

Do not deploy the application change without migration 013. The returned UI adds
validated `plot_size` metadata to layout saves; migration 010 alone rejects that
field.

## Preview acceptance checks

- Public discovery loads all 15 sample farms.
- Search, quick filters, region and nutrition objectives update cards and map.
- Every plotted card number matches its marker number.
- Marker numbers are upright; public cards and tooltips do not show T1/T2.
- Desktop More and the mobile menu retain all destinations; account action is
  last when signed in.
- Customers Buy, Farmers Sell and Farmers Grow labels are consistent in the live
  experience.
- Root Route opens without covering its final stop and prioritizes matching
  produce when selected.
- Alert forms remain clearly labelled demonstrations and do not claim that a
  message or subscription was saved.
- Community Board cards align at desktop, tablet and phone widths.
- Mission and Design Journey links and source links open as expected.
- An authorized member can create a new plot only after entering whole-foot
  dimensions from 1-500 ft wide and 1-200 ft long.
- A 500 x 200 ft plot saves and reloads with its dimensions.
- 501 ft width, 201 ft length, fractions, unknown layout fields, T2 writes,
  unrelated-farm writes and anonymous writes are rejected.
- Existing Grow layouts without `plot_size` still load and retain their saved
  crops, revisions, harvests and recovery behavior.
- Farmers Sell updates and Admin feedback/export still work.

## Automated validation

Run from the repository root:

```powershell
npm.cmd ci
npm.cmd run lint
node --test tests/*.test.cjs
npm.cmd run build
```

The optional authenticated Grow browser harness is
`tests/grow-flow.browser.cjs`. It requires the Playwright setup documented in
`docs/GROW-USABILITY-RELEASE.md` and a production build served on port 3100.

The disposable PostgreSQL contract tests are `tests/grow-layout-db.sql` followed
by `tests/grow-layout-archive-db.sql`. Never run those fixture files against the
live Supabase project.

## Rollback boundary

If preview validation fails, do not merge the Git branch. Migration 013 is a
backward-compatible function replacement: older three-field layout documents
remain accepted. Rolling the application back therefore does not require
deleting farm records or reversing the migration.
